# 手工验收清单（真实 DSH profile）

> **要在真实 DSH profile 上确认什么**：构建产物（`ui/client.js`）能加载 → 四个槽位能注册 → 宿主 props 形状与 glue 对齐 → 核心链路（组装 → 写入草稿 → 发送）行为正确。
>
> **耗时**：安装启动 3 分钟 + 快线 6 分钟 + 发布门槛 4 分钟 + 观测 3 分钟。
>
> **为什么不能省**：仓库内的自动化测试覆盖纯逻辑断言、渲染级初始状态（`test/render-smoke.test.js`，真实 react-dom/server）与源码/产物文本断言，但**交互（点击 / 事件）与宿主 props 形状**仍覆盖不到。`test/dsh-slots.test.js` 会读真实构建产物做包含性检查，但 slots 服务是模拟对象——它只能证明「产物能调用注册接口」，不能证明目标 DSH 版本喂进来的 props 形状与之一致。这一条只能靠真实 profile。
>
> **章节标题里的「N 项」有门禁看守**：`npm run check` 会逐章比对「标题声明的条目数 vs 该章节里实际存在的条目数」（条目可以是表格行 `| F1 | …` 或小节标题 `### F1 …`）。新增或删除验收项后请同步改标题里的数字，否则门禁会失败并点名是哪一章；判定逻辑见 `scripts/lib/manual-qa-count.mjs`。

## 0. 先填被测版本

**Desktop App 专项**：先运行 `npm run check:dsh-app -- /path/to/deepseek-harness`，再在 App 的 Plugins 页安装插件；Web profile 的安装结果不计入 App 验收。打开暗色主题，分别在宽窗口与窄窗口检查科研工具详情卡的准备中／执行中／完成或失败状态，确保文字可读、不横向溢出。用测试数据在 Web 导出迁移包，在 App 选文件预览；确认预览时未写入，下载本端备份后导入，刷新并复核证据、知识、资产及关联，再重复导入确认无稳定 ID 副本。迁移流程详见 [App 迁移说明](APP-MIGRATION.md)。

**Desktop 新增面专项**（本轮新增/改动的入口，App 里同样要各过一遍）：① 插件详情页的**行配置预设**——按 P5 在 App 里点两行「应用」，按钮变「已应用」，刷新后值仍是新预设（App 与 Web 共用同一份客户端，但 profile 与 `localStorage` 是分开的，别把 Web 里的结果当 App 的）；② 插件详情页的**规模徽章与「复制诊断」**——徽章数字应等于目录规模，点「复制诊断」后剪贴板里真的有诊断文本（App 的自定义协议是 secure context，剪贴板 API 可用；若点了没反应就是这条被破坏）；③ **「回到会话」在 App 里要真的能跳**——按 P4 从 Plugins 详情页点头部按钮，主区应切回当前会话；该会话此前停在科研工作台时应一并恢复（App 0.2.2-rc.5 具备宿主会话导航面；若按钮整块不出现，说明服务探测把可用通道误判成缺失）；④ 工作台里的**数据库查询**在 App 内要能出结果（它是唯一以 `location.href` 为基准拼 URL 的请求，用来验证客户端不依赖页面源是 http(s)）；⑤ **工作台「在新会话开始」**——按 F5 在 App 里点一次，应新建会话并把提示词预填为草稿（App 0.2.2-rc.5 已支持 `prompt` / `whenDraftExists`）；⑥ **悬浮入口形态的浮层位置**——在插件详情页把入口形态切到「悬浮」，确认草稿增强的浮动钮与真沉淀伴生钮出现在右下角预期位置、点开面板不被裁（0.2.2 起 composer seat 是 fixed 后代的 containing block，这两处浮层已改为 portal 到 body；若位置偏移或被裁，就是 portal 回归）。

**Desktop Claim 专项**：在 App 的测试课题中进入「科研工作台 → 本次研究 → 研究资料 → Claim 审阅」。用带公开 DOI 的测试段落提取候选，勾选后登记；确认刷新后仍能看到来源位置。先点「发布检查并导出」，应列出待人工确认项且不下载发布文件；再点「Agent 审阅」，应显示建议但仍为待核验；人工填写评估人、理由并关联测试证据后确认，再次发布检查应通过并下载 JSON。最后在窄窗口确认按钮、建议与阻断提示可见。Agent 调用要使用当前 App 会话已配置的模型路由；不要在生产课题里制造测试 Claim。此项必须在真实 App 中执行，浏览器回归和静态契约检查不能替代。

## 1. 安装与启动（约 3 分钟）

本仓库无运行时依赖，不需要 `npm install`。

> **环境前置：`dsh plugin` 会调用 PATH 上的 `pnpm`，其 store 布局主版本必须与目标 profile 记录的一致。** 否则命令会以 `ERR_PNPM_UNEXPECTED_STORE` 直接失败（失败是原子的，不会产生任何改动）。先校验：
>
> ```bash
> grep storeDir ~/.dsh/profiles/web/node_modules/.modules.yaml   # 例：…/store/v11
> pnpm --version && pnpm store path                             # 例：v10 → …/store/v10 ← 不一致
> ```
>
> 末段 `v11` 对应 pnpm 11.x、`v10` 对应 10.x。不一致时改用**与记录一致的主版本**执行，例如隔离安装 `npm i pnpm@11` 后把其 bin 目录前置到 PATH。

```bash
npm run build
dsh plugin --profile web add <path-to-this-repo>
```

刷新浏览器，打开一个**已有会话**。

**预期**：会话视图区出现「科研工作台」；输入框出现「科研辅助」，菜单提供「选流程」和「加资源」。支持的宿主会在浮层顶栏显示自动科研辅助开关，搜索栏旁可整理当前提问。短窗口中应能直接看到流程结果，并滚动到最后一条。
不出现 → 停止，按 §4 的 L1/L2 定位。

可用 `npm run test:dsh-web` 启动隔离 Web 环境，核对工作流入口和插件路由。完整草稿、模型执行与桌面交互仍按下列清单验收。

## 2. 快线（5 项，约 8 分钟）

任一项失败即停止并记录。

### F1 槽位注册无重复

**操作**：查看视图标签区与输入框两侧，同时打开浏览器控制台。

**预期**

- 「科研工作台」**恰好出现一次**；输入框科研辅助出现一次；草稿增强入口按 Plugins 详情页「运行状态」里的**入口形态**设置只出现一种（内联 = 从科研辅助菜单打开、无悬浮圆钮；悬浮 = 右下角悬浮钮 + 沉淀伴生圆钮各一个）；
- 控制台无 `undefined is not an object` / `register` 相关报错。

**判定**：重复出现 = 残留旧版本安装或 disposer 未执行；完全不出现 = 槽位名与宿主不匹配。

### F2 四分区可切换

**操作**：在「科研工作台」内切换「本次研究」和「科研工具」，检查研究资料、证据关系和科研工具内四项操作。

**预期**：默认落在「本次研究」。进入「科研工具」可切换「选流程」「用方法」「查来源」「我的」；研究资料与证据关系从「本次研究」打开。

**判定**：标题错位、内容空白、切换报错 → L4 渲染层。

### F3 写入不发送 + 只发一次

**操作**

1. 在「科研工具 → 选流程」选中 `审阅论文`；
2. 填写至少一个必填参数；
3. 点「写入输入框」；
4. 观察输入框；
5. 再点「发送到当前会话」。

**预期**：步骤 4 出现完整 Prompt 且**未自动发送**；步骤 5 **只产生一条**用户消息。

**判定**

| 现象 | 定位 |
| --- | --- |
| 步骤 4 直接发出消息 | `setDraft` 被误接成 `submit` → L3，查 `dsh/standalone-glue.js` 的 props 取值 |
| 步骤 5 出现两条消息 | `submit()` 被调用两次（绑定重复）→ L3 |
| 输入框始终为空 | 草稿写入路径断开 → L5 状态/存储 |

### F4 切换会话不串台

**操作**：切换到另一个会话，再切回，重复 F3 的步骤 3–5。

**预期**：消息落在**当前**会话，不会写进上一个会话。

**判定**：串台 → `sessionId` 未随会话刷新，或 `inputActions` 被跨会话缓存 → L3。

### F5 在新会话开始（0.2.1-rc.1+）

**操作**

1. 在「科研工具 → 选流程」选中 `审阅论文`，填写至少一个必填参数；
2. 点「在新会话开始」；
3. 观察是否新建/切到一个空白会话，且输入框**已预填**研究运行提示词（含 `【研究运行】ID：…` 段）；
4. 在已有草稿的空白会话里再点一次（先用「写入输入框」写一句话），确认提示词是**追加**而非覆盖，且附件仍在。

**预期**：步骤 3 预填完整 Prompt 且**未自动发送**；步骤 4 在 0.2.1-rc.3+ 上原有文字保留、提示词另起段落追加，附件不丢；在 rc.1/rc.2 上 `whenDraftExists` 不被识别，已有草稿会被**保留**（不追加、不覆盖），新建的空白会话仍照常预填。`0.1.7` / `0.2.0` 线没有草稿预填通道，按钮**整块不出现**（不是灰按钮、不是点了没反应）。

**判定**

| 现象 | 定位 |
| --- | --- |
| 出现按钮但点击无反应 | 宿主 `startSession` / `requestDraftInitialization` 探测误判 → L3，查 `src/lib/host-navigation.js` 与 `dsh/standalone-glue.js` 的 `launchSession` |
| 新会话里输入框为空 | 宿主接受了 `startSession` 但未应用 `prompt` → 检查草稿通道是否探在 `conversation` 服务上（`uiConversation` 没有 `input`） |
| 原有草稿被覆盖 | `whenDraftExists` 被误传成 `replace` → L3 |
| 直接发出消息 | 预填被误接成 `submit` → L3 |

## 3. 发布门槛（2 项，约 4 分钟）

§2 全绿后再做。

### R1 卸载无残留

**操作**（三步，需要 **1 次重启**）：

```bash
dsh plugin --profile web remove dsh-research-kit   # 1) 卸载
# 2) 重启 profile 并刷新页面 → 核对控件消失
dsh plugin --profile web add <path-to-this-repo>   # 3) 重装
```

**预期**：

- **卸载后**：以下五处都不得再出现 `dsh-research-kit`——`package.json` 的 `dependencies`、`package.json` 的 `dsh.profile.bundles`、`pnpm-lock.yaml`、`node_modules/.modules.yaml`、`--dump-config` 合成树；
- **重装后**：`package.json` 应逐字节回到卸载前，`bundles` 只 1 条，合成树只 1 层，重新打开会话时各控件**仍只出现一次**。

> **卸载在运行态不立即生效。** 插件树在 profile 启动时合成，重启前旧实例仍在服务（DSH 自身的卸载日志也会标注「待重启生效」）。因此「卸载无残留」必须**重启后**才能判定运行态。

### R2 降级不崩

**操作**：构造一次宿主动作缺失（禁用对应能力，或在 devtools 中断开 `inputActions`）。

**预期**：相关按钮禁用并给出说明文案，视图不崩溃。

## 4. 失败定位树

| 症状 | 层 | 首要检查点 |
| --- | --- | --- |
| 插件根本没被加载 | L1 加载 | `package.json` 的 `main` / `type: module`；`cordis.patch.yml` 的 id 与安装名是否一致 |
| 加载了但没有任何槽位 | L2 注册 | `dsh/slot-registry.js` 的 slot 名是否与目标 DSH 版本一致 |
| 槽位重复出现 | L2 注册 | 是否残留旧版本安装；`registerResearchSlots` 返回的 disposer 是否被调用 |
| 槽位在但视图空白 / 报错 | L4 渲染 | 浏览器控制台首个 React 错误栈；`src/ui.js` 的组件契约 |
| 写入草稿变成直接发送 | L3 契约 | `dsh/standalone-glue.js` 中 `inputActions` 的取值与调用点 |
| 消息发两次 | L3 契约 | `submit` 的调用是否被重复绑定 |
| 切换会话后串台 | L3 契约 | `sessionId` 的更新路径 |
| 直查返回 503 / 增强提示「尚未建立模型路由」 | L5 路由 | `index.js` 三条路由是否注册；`ctx.sessions` 惰性兜底是否命中 |

**修复位置原则**

1. 宿主 props 形状不符 → **只改 `dsh/standalone-glue.js`**，不要让 React 模块去读宿主私有数据；
2. `vendor/promptkit-embed.js` **不得改动**——其 SHA-256 被 `npm run check` 锁定，改动会导致校验失败；
3. 分区结构变更只改 `src/lib/console-sections.js`，并同步 `src/research-console.js` 的 `SECTION_VIEWS`，否则 `test/research-console.test.js` 会失败。
